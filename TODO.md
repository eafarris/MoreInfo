# TODO: Docs-vs-Reality Gaps

Generated by auditing http://moreinfo.eafarris.com/docs against the current
codebase (2026-08-07). Everything below is a claim the documentation makes
that the app does not yet fully deliver. Anything the docs describe that was
verified as already implemented is *not* listed here.

Note: several items marked "not yet implemented" in CLAUDE.md's own feature
checklist (`@waiting` context tag, priority escalation, overdue coloring,
hover preview cards, Settings panel, drag-and-drop widget reordering) turned
out to already be implemented in the code. CLAUDE.md's checklist should be
refreshed separately from this list — see the note at the bottom.

## 1. Search: no dedicated `title:` filter

`/docs/full-text-search` documents `title:roadmap` as searching "only note
titles." `apply_known_filter` (`src-tauri/src/lib.rs:2508-2548`) only
recognizes `tag`, `category`, `in`, `after`, `before` as known filter keys —
there is no `title` case. A `title:` query currently falls through to the
generic `meta_filters` path (matching against the `file_metadata` table),
which is not guaranteed to have the same semantics as "search only the
title field."

- [ ] Add an explicit `title:` filter case that scopes the FTS/LIKE match
      to the title column only, and confirm it doesn't silently rely on
      `title` happening to exist as a metadata row.

## 2. Wiki-link autocomplete is prefix matching, not fuzzy

`/docs/wiki-links` claims "MoreInfo shows a **fuzzy-search** autocomplete of
all note titles." `wikiLinkSource()` (`src/editor.js:1103-1160`) only does
`p.title.toLowerCase().startsWith(query)` (plus alias prefix match) — a
straight prefix check, not fuzzy matching. Typing a substring that isn't at
the start of the title (or a scattered-letters fuzzy match, e.g. "prjrd" for
"Project Roadmap") currently returns nothing.

- [ ] Either implement real fuzzy matching (e.g. subsequence/Levenshtein-ish
      scoring) in `wikiLinkSource`, or narrow the docs' wording to "prefix
      search" if fuzzy matching isn't planned. Since the instruction is to
      list app work, default to implementing fuzzy matching.
